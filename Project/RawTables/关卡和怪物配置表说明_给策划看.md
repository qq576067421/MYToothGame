# 当前项目关卡和怪物配置表说明

更新日期：2026-05-08

适用范围：
- `D:\lichunlin\MYToothGame\Project\RawTables`
- `D:\lichunlin\MYToothGame\Project\public\Tables`
- `D:\lichunlin\MYToothGame\Project\GameProject`

这份文档的目标不是讲程序实现细节，而是帮助策划快速理解：
- 当前项目里，关卡和怪物相关配置主要放在哪几张表。
- 每张表大概负责什么。
- 表和表之间是怎么串起来的。
- 如果要调一关、调一只怪、调一个角色成长，应该优先看哪张表。

## 1. 先说结论：策划看表的推荐顺序

如果只是想快速理解一关内容，建议按这个顺序看：

1. `g关卡表.xlsx`
2. `g 怪物表.xlsx`
3. `td 塔防关卡防守角色表.xlsx`
4. `j 角色表.xlsm`
5. `td 塔防角色成长表.xlsx`
6. `jn 技能表.xlsx`
7. `zd 子弹表.xlsx`
8. `s 属性表.xlsm`

可以把它理解成一条主链路：

`关卡表 -> 刷出哪些怪 -> 这一关上哪些防守角色 -> 角色/怪物各自带什么技能和属性 -> 技能是否发射子弹 -> 子弹怎么飞`

## 2. 当前项目里最核心的表

### 2.1 `g关卡表.xlsx`

核心 sheet：
- `t_stageBean`

它是“关卡总控表”，决定一关最核心的战斗内容，包括：
- 关卡 ID
- 关卡名
- 场景图
- 普通怪配置
- Boss 配置
- 首波延迟
- 波次间隔
- 总波数
- 精英怪配置
- 精英波次
- Boss 波次
- 主题编号
- 无尽模式主题池
- 无尽模式主题切换时间

当前导出字段可以直接看到：
- `t_monster_ids`：普通波刷怪
- `t_elite_ids`：精英怪
- `t_boss_ids`：Boss
- `t_elite_waves`：哪些波刷精英
- `t_boss_waves`：哪些波刷 Boss
- `t_theme_id`：关卡属于哪个主题

这张表最适合回答的问题：
- 这一关总共打几波？
- 哪几波有精英？
- 哪几波有 Boss？
- 这关属于哪个主题？
- 无尽模式从哪些主题关卡池里切换？

补充理解：
- `t_monster_ids` / `t_elite_ids` / `t_boss_ids` 里的每一组数据，本质上是在描述“刷哪种怪、等级是多少、数量是多少”。
- 当前工程里，普通怪和精英怪最终走的是 `t_smallMonsterBean`，Boss 走的是 `t_monsterBean`。

### 2.2 `g 怪物表.xlsx`

这个工作簿里当前有两个核心 sheet：
- `t_smallMonsterBean`
- `t_monsterBean`

建议这样理解：
- `t_smallMonsterBean`：普通怪、精英怪主表
- `t_monsterBean`：Boss 主表

#### A. `t_smallMonsterBean`

主要负责普通怪/精英怪的基础定义，包括：
- 名字、描述
- Prefab/头像资源
- 普攻技能
- 被动技能
- AI
- 属性表引用
- 等级模板引用
- 怪物类型
- 到基地扣血量

其中比较值得策划重点关注的字段有：
- `t_name`
- `t_model`
- `t_normal_skill_id`
- `t_passive_skill_id`
- `t_ai_id`
- `t_property`
- `t_level_class`
- `t_monster_kind`
- `t_base_damage`

这张表最适合回答的问题：
- 这只普通怪/精英怪是谁？
- 它走什么模型和头像？
- 它用什么普攻/被动？
- 它的数值引用哪套属性？
- 它撞基地时扣多少血？

#### B. `t_monsterBean`

主要负责 Boss 定义，包括：
- Boss 名字、描述
- 模型
- 普攻技能
- 主动技能组
- 被动技能组
- AI
- 属性表引用
- 等级模板引用
- Boss 技能前摇时间
- 到基地扣血量

重点字段：
- `t_normal_skill_id`
- `t_skill_id`
- `t_passive_skill_id`
- `t_property`
- `t_level_class`
- `t_td_boss_skill_prepare_ms`
- `t_base_damage`

这张表最适合回答的问题：
- 这关最后出的 Boss 是谁？
- 它除了普攻外还有哪些技能？
- 它的数值强度来自哪套属性/等级模板？
- 它到基地后扣多少血？

## 3. 和关卡强相关的辅助表

### 3.1 `td 塔防关卡防守角色表.xlsx`

核心 sheet：
- `t_tdStageGuardRoleBean`

作用很直接：
- 决定每一关默认上场的 4 个防守角色配置 ID。

当前字段非常少，核心只有：
- `t_id`
- `t_guard_role_ids`

其中 `t_guard_role_ids` 的顺序对应：
- `guard_1`
- `guard_2`
- `guard_3`
- `guard_4`

这张表最适合回答的问题：
- 当前这关默认给玩家哪 4 个防守角色？
- 某一关的守塔角色阵容是不是要换？

如果策划想调“这一关上谁”，优先改这张表。

### 3.2 `td 塔防角色成长表.xlsx`

核心 sheet：
- `t_tdRoleGrowBean`

作用：
- 定义塔防角色在 1~5 级时挂哪些运行时 Buff。

当前核心字段：
- `t_id`
- `t_runtime_buff_ids`

当前配置形式可以理解为：
- 一组角色成长配置，对应 1~5 级各自挂哪些常驻 Buff。

这张表最适合回答的问题：
- 某个防守角色升到 2/3/4/5 级后，会拿到哪些成长效果？
- 某个角色的成长偏数值型还是机制型？

如果策划想调“角色升级后变强的方式”，优先看这张表，再联动 Buff 表。

## 4. 角色、技能、子弹、属性这几张二级关联表

这些表不是“关卡表”，但关卡和怪物最终都会走到这里。

### 4.1 `j 角色表.xlsm`

核心 sheet：
- `t_heroBean`

作用：
- 定义防守角色本体。

当前关键字段包括：
- `t_normal_skill_id`
- `t_skill_id`
- `t_model`
- `t_property`
- `t_level_class`

这张表最适合回答的问题：
- 某个防守角色带什么普攻和主动技能？
- 它的模型、属性、等级模板分别引用哪一套？

### 4.2 `jn 技能表.xlsx`

核心 sheet：
- `t_skillBean`

作用：
- 定义技能本身。

当前关键字段包括：
- 基础攻击值
- 每级成长值
- 冷却
- 施法距离
- 伤害计算方式
- 伤害参数
- 是否需要目标
- 子弹 ID
- Buff 列表

这张表最适合回答的问题：
- 某个技能是单体、范围还是施法者周围伤害？
- 它带不带子弹？
- 它的伤害和冷却怎么成长？
- 技能释放时附带哪些 Buff？

### 4.3 `zd 子弹表.xlsx`

核心 sheet：
- `t_bullet`

作用：
- 定义子弹/弹道层。

当前关键字段包括：
- 子弹类 ID
- 子弹特效资源
- 移动速度
- 最长飞行时间
- 重力

这张表最适合回答的问题：
- 某个技能发射的是哪种子弹？
- 子弹飞多快？
- 子弹特效用哪个资源？

### 4.4 `s 属性表.xlsm`

核心 sheet：
- `t_propertyBean`

作用：
- 定义角色和怪物的基础数值模板。

当前覆盖内容很多，主要包括：
- 攻击距离
- 力量/智力/敏捷及成长
- 生命
- 法力
- 护甲
- 法抗
- 移动速度
- 攻速
- 基础攻击间隔

这张表最适合回答的问题：
- 这只怪为什么这么肉/这么快？
- 这个角色为什么射程更远、攻速更高？

### 4.5 `t_levelBean` 对应的等级模板

来源：
- 当前导出的客户端表里有 `t_levelBean.csv`

作用：
- 给角色和怪物提供等级成长模板，例如：
  - 基础经验
  - 每级经验增量
  - 死亡经验
  - 死亡金币

这张表更偏系统层，不是策划看关卡时第一优先，但当你想理解“同一只怪换等级后数值/产出如何变化”时，它很关键。

## 5. 当前项目里，表和表之间怎么串

可以按下面这张关系图理解：

### 5.1 关卡内容链

`g关卡表.xlsx / t_stageBean`

决定：
- 普通怪列表
- 精英怪列表
- Boss 列表
- 波次节奏
- 主题信息

然后继续关联到：
- 普通怪/精英怪 -> `g 怪物表.xlsx / t_smallMonsterBean`
- Boss -> `g 怪物表.xlsx / t_monsterBean`

### 5.2 怪物战斗链

`t_smallMonsterBean` 或 `t_monsterBean`

继续关联到：
- 技能 -> `jn 技能表.xlsx / t_skillBean`
- 属性 -> `s 属性表.xlsm / t_propertyBean`
- 等级模板 -> `t_levelBean`
- 模型/资源 -> `t_modelBean` 或怪物表自身资源字段

如果技能里填了子弹：
- 再继续关联到 `zd 子弹表.xlsx / t_bullet`

### 5.3 关卡防守角色链

`td 塔防关卡防守角色表.xlsx / t_tdStageGuardRoleBean`

决定：
- 这一关默认上哪些守塔角色

继续关联到：
- 角色本体 -> `j 角色表.xlsm / t_heroBean`
- 角色成长 -> `td 塔防角色成长表.xlsx / t_tdRoleGrowBean`
- 技能 -> `jn 技能表.xlsx / t_skillBean`
- 属性 -> `s 属性表.xlsm / t_propertyBean`

## 8. 阅读和维护时的几个注意点

### 8.1 不要只改导出的 CSV

正式维护源头应当是：
- `RawTables` 里的 Excel

`public\Tables` 下的 CSV 更适合：
- 对照字段
- 快速查当前导出结果
- 核对有没有成功导表

不建议把 CSV 当正式编辑源。

### 8.2 关卡表里的怪物 ID，并不是所有怪都来自同一张 sheet

这是当前项目一个很容易看错的点：
- 普通怪/精英怪 -> `t_smallMonsterBean`
- Boss -> `t_monsterBean`

所以在看一关的刷怪配置时，不能只看一个怪物 sheet。

### 8.3 数值经常是“多表组合生效”

例如一只怪最终强不强，通常不只取决于怪物表一行，还可能同时受这些内容影响：
- 怪物表里挂的技能
- 怪物表里挂的属性表
- 怪物表里挂的等级模板
- 技能表里的伤害和冷却
- 子弹表里的弹道速度

也就是说：
- `怪物表` 更像“总入口”
- `属性表 / 技能表 / 子弹表` 更像“细分模块”

### 8.4 角色成长不要只看角色表

如果想看“这个角色升到 3 级/5 级为什么效果会变”，重点通常不在 `角色表` 本身，而在：
- `td 塔防角色成长表.xlsx`
- `Buff` 相关表
- `技能表`

## 9. 给策划的一个最实用记忆法

如果只记一句话，可以记成：

`关卡表决定这一局刷什么，怪物表决定怪是什么，角色表决定我方是谁，成长表决定升级后怎么变，技能表和子弹表决定打出来是什么效果。`

如果只记两张表：
- 看一局内容先看 `g关卡表.xlsx`
- 看一只怪先看 `g 怪物表.xlsx`
